# 03 · 图片附件使用说明（面向用户）

> 上位文档：[`../image-attachments.md`](../image-attachments.md)
> 这一页只讲「怎么用、有什么限制」。为什么这么实现见 [`01`](01-placement-decision.md) 与 [`02`](02-storage-and-gc.md)。

---

## 怎么添加图片

三种方式：

### 1. 剪贴板粘贴（Ctrl/Cmd+V）

- 截图后直接按 **Ctrl/Cmd+V** 粘贴到输入框
- 不需要先把截图保存成文件 —— 截图工具把数据放进剪贴板就够了
- 支持一次粘贴多张

### 2. 从项目里拖进来

- 在 VS Code 资源管理器里选中图片，**按住 Shift** 拖进输入框
- 支持 PNG、JPEG、GIF、WebP、SVG

### 3. 文件选择器

- 点输入框的 **+**（Attach）按钮选文件，支持多选

---

## 缩略图条

添加成功后，图片以 48px 方块显示在输入框上方：

- **横排滚动** —— 多张不换行，横向滚动
- **悬停 / 键盘聚焦** —— 显示高亮环；可以 Tab 逐个走到每张图
- **删除** —— 右上角 ×，或聚焦后按 Delete
- **打开预览** —— 点击缩略图，或聚焦后按 Enter

**失效附件**：如果某张图的数据已经不在磁盘上了（比如手动清理过 `~/.tomcat`，或草稿在另一台机器上打开），那张缩略图会显示为失效状态并附一个移除按钮，**草稿的其余部分不受影响** —— 文字和别的图片都还在。

---

## 图片预览

点任意缩略图（未发送的或历史消息里的都可以）会打开一个独立的编辑器标签：

| 操作 | 方式 |
|---|---|
| 缩放 | `+` / `-` 按钮或快捷键；`0` 适应窗口 |
| 翻页 | ←/→ 按钮、键盘方向键、或点底部缩略图条 |
| 复制 | ⧉ 按钮。剪贴板不接受原格式时会自动转成 PNG |
| 另存为 | ↓ 按钮 |
| 关闭 | Esc 或 ✕ |

预览用的是**原始全尺寸图片**，不是放大的缩略图，所以放大后是清晰的。

## 草稿会保留到什么程度

未发送的内容（文字 + 图片附件）会自动保存。以下情况**都能恢复**：

```text
  切到别的会话再切回来        ✓
  webview 重新加载            ✓
  扩展重启                    ✓
  VS Code 完全退出重开         ✓
  tomcat 后端进程崩溃或升级    ✓   ← 草稿不依赖后端健康
```

**草稿跟着工作区走。** 同一个工作区的两个窗口如果同时编辑同一个会话，后保存的那份会覆盖先保存的（和 VS Code 自己的聊天输入框行为一致）；不同工作区的窗口互不影响。

草稿文件在扩展的存储目录下（`composer-drafts/<会话 id>.json`），里面**只有文字和图片的引用，没有图片数据本身** —— 所以它很小，打字时的保存开销可以忽略。

### 升级注意

**从旧版本升级后，未发送的草稿会被清空一次。** 旧版本把草稿存在后端的另一个位置，这次改动没有做数据迁移（草稿是临时内容，为一次性格式变更写迁移代码不划算）。升级后新写的草稿一切正常。

## 格式与大小限制

| 类型 | 支持格式 | 单个上限 |
|------|---------|---------|
| 图片 | PNG、JPEG、GIF、WebP、SVG | 4.5 MB |
| 文件 | PDF | 25 MB |

**SVG 的特殊处理**：模型的视觉接口不认 SVG，所以添加 SVG 时会在本地转成 PNG 发给模型；而**你在界面里看到的仍然是原始 SVG**（矢量渲染，放大不模糊）。如果转换失败，会退而把 SVG 源码作为文本发给模型 —— 对图标和 logo 这类内容，模型读源码往往比看图更准。源码超过 50KB 时不内联。

---

## 模型兼容

- 图片总是会随消息发送给后端
- 如果当前模型不支持视觉输入，添加图片时会有提示，但图片仍然保留在草稿里（换个模型就能直接发）

---

## 历史消息里的图片

- 已发送消息里的图片会随会话历史一起恢复
- 点历史缩略图可以再次预览、另存为（不能删除 —— 历史是不可变的）
- 删除会话时，它的草稿和历史一起清理

**关于磁盘占用**：图片数据存在 `~/.tomcat/…/sessions/attachments/` 下。缩略图和已发送图片都是可以重建的，空间紧张时会自动按最近最少使用清理（默认上限 256MB），清掉只会让下次打开老会话慢一点，不会丢东西。未发送的草稿图片永远不会被自动清理掉。
